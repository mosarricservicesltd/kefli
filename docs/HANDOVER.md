# Handover: picking Kefli up on another computer

Written on 6 October 2026, when the work moved off the laptop it started on. Everything needed is in this repository; this page says where things are, what is in flight, and how to set a new machine up. `CLAUDE.md` stays the project's standing brief and Claude Code reads it automatically; this page adds the state of play.

- **Contract v1.12** (`shared/contract/contract.md`) is the source of truth for the protocol. v1.12 (14 October 2026) sets the fair use of Kefli's server: a library keeps up to 50 MB of text there and uploads at most 20 MB a day, and past either a save goes out without its text, which stays on the phone and counts as not backed up; `GET /account` reports the figures (its section 11.1, flow decision 117; built the same day and the next, below). On 14 and 15 October, before any release, the same version took in the rules the hardening and the final review settled (section 11.1, items 8 to 22; flow decision 118): a save's address keeps no user name or password and takes a canonical only from the page's own site, an item has a ceiling, a save keeps at most 5 MB of text, a client follows redirects only to public addresses and none from the API, a save whose page can't be had is in time published without its text, an answer a relay doesn't finish with EOSE is no answer, every blob counts as at least 4,096 bytes, and the operator's servers bound what one client may ask of them, the requests it keeps in flight and the pace of their bodies included. v1.11 (14 October 2026) has a browser consent to each pairing with a proof signed by its own key, which `POST /devices` now requires, and a library sign a browser's release in a move, so phones and extensions from before it must update; it also writes down the operator's limits on everyone together and what the audit's other fixes changed (its section 11.2, flow decision 116). v1.10 (13 October 2026) keys every save's address with a per-library key kept in a `kefli/library-key` record, so a page's URL can't be tested against a library, carries each save's hash inside its encrypted item, and drops the browser label from `POST /devices` (its section 11.3; the audit's F5 and F30). v1.9 the same day lets the person add relays of their own in Advanced and remove the ones they added (its section 11.4, flow decision 113). v1.6 (11 October 2026) keeps citation markers and Wikipedia's reference lists out of the spoken projection and parses linked PDFs on the phone (its section 11.7); ## Known risks left

- **Addresses checked as they are written** (decision 119, kept for 1.0): a public name for a private address, DNS rebinding, and the render WebView's requests that Android doesn't show Kefli all pass; closing them needs a native HTTP client or a process-wide proxy.
- **Chinese and Japanese text** (decision 119, for 1.1): a paragraph written without spaces is one word and one sentence, so the highlight lights the whole paragraph, the clock counts it as one word, and a long paragraph starts late and pauses between its pieces; splitting at the script's own stops changes the projection's version and every client's derive, a protocol round with its own fixtures, after launch.
- **Small address edges:** 192.0.0.0/29 passes as public, and on IPv6-only mobile networks Android's 464XLAT gives the phone 192.0.0.4, though with no cleartext only a TLS service on the phone could answer; `isPublicWebUrl` takes off one trailing dot only, so `localhost..` reads as public, a host OkHttp refuses anyway; a user name that begins `filesystem.local` reaches expo/fetch's file handler, which can only answer 404 there, and user info comes off before every fetch; and You loads a nostr user's own profile picture, any https address in their kind 0, through expo-image, outside `net/http`'s checks (`data/profile.ts`). `pickXLink` (`x.ts`) takes a link in X's embed that isn't a `t.co` link without the public-address check, though X wraps every link in `t.co`, so only X's own embed could name one. - **Floods of wraps:** a sustained flood at the relay's limits (57,600 wraps in the two-day window) can still hide a backdated save beneath ten answers; every wrap the live subscription delivers sets off a full drain, and a deep read every 15 minutes still downloads up to 4,500 wraps (72 MB); a registered key is held to the recipient ceilings since decision 119. The fix is `redirect: 'error'`. Its Blossom upload and delete and its `defaults.json` fetch follow them too, wherever they go, against contract 1.12's sections 3.1 and 5 (extension spec 15).

Deleting a text another phone uploaded frees room this phone can't reckon. A move's copy names the first mirror S's newest event named, unchecked. - **Shares and the voice:** `KefliShareModule.finish` for a spool whose sheet has gone closes whichever share sheet is in front, so in a split screen an old sheet's late finish can close another share's; a direction mark between a whole-share link and its full stop stays in the saved address, percent-encoded; a process killed between the spool's synced temporary file and its rename loses the share; and at the engine's limit a cut can part a letter from its combining accent, and text joined by U+200B is cut inside a word (each needs 2,000 characters with no space or stop).
- **Pages:** on a network that carries nothing while Android still calls it online, a run can still fail up to two old saves wrongly, and one more in the quick re-run (the three-day rule's share of this closed with decision 119, its failures counting towards the run); a text file written before its transaction fails, for a save re-keyed and then deleted before the retry, stays on the disk with no row naming it; and in `save.ts` `savedParsed`, a `queueSave` that throws after staging (`SQLITE_FULL`) leaves the staged blob, which `sweepStaged` never finds since it reads rows (older than this branch; an unstage on failure, as `pending.ts` `settle` does, would close it).
- **Server:** a copy of a blob already stored costs nothing against the day, so one library can send the same 8 MB body again and again (300 copies, 2.4 GB, were all taken), though the client pays for every byte and a copy is no longer written; `DELETE /account` on a full library of tiny blobs holds keflid's one database connection for 1.4 to 5.6 s; another library deleting the same blob between an upload's commit check and its record can take a library's day or quota one blob, 8 MB at most, past its limit; an account disabled or a browser revoked while an upload is on its way still gets it recorded, a revoked browser's capture counting 14 days at most; `AddDevice`'s upsert and its `DELETE FROM gone` aren't one transaction, the root of a browser authorised yet still on the gone list, whose uploads are now accepted; on a new box the blobs folder itself is never synced into `/var/lib/kefli`; whether the VPS disk honours fsync is untested; and a registered key can still name a removed key in the `p` tags of other kinds, which no sweep removes. Beside the guard: Caddy's own server on port 80, there to redirect, isn't held to `read_body` and keeps a connection while a body trickles in, bounded only by nftables' 512 connections a client, and holding it to the limit needs explicit `http://` sites that would replace Caddy's own redirects and certificate checks; over HTTP/1.1 Caddy holds keflid's early answer until the client's body is in or its 20 minutes are up, where over HTTP/2, which phones and browsers use, it answers at once; nftables counts IPv6 connections by the /64 only; a mirror's address counts as one client, so it has at most 32 fetches in flight; a client that sends `Expect: 100-continue` through Caddy can still lose an early answer as a 502, as before the guard, though no phone or browser sends it; and the guard's own refusals close at once, so through Caddy one to a body of about 100 to 250 KB can come back as a 502, which both clients send again as they do a 429.
- **The move's last look at the old inbox** fails without a word when the relay can't be reached or cuts its answer short, and S is retired all the same (`inbox.ts`, `runner.ts`), so a browser save waiting in the old inbox then is never moved: the drain would have to say whether it reached the relay, and a check of its cursor inside the move would let a flood of S's inbox hold the move. Beside it, Delete my data dates a generated identity's list kind 5 by the phone's clock rather than after the newest list it holds (`listDeletion`), so with another phone's clock ahead the indexer keeps the old list; `nextListTime` would close it.
- **Left open from the audit:** a per-offer check on the six digits, so the server could delete an offer after three wrong guesses (F8; it needs a contract change across the protocol, phone and server; the caps on everyone together stand in, with each block of addresses, an IPv4 /24 or an IPv6 /48, held to 10 of the 100 misses and an IPv6 /48 to 20 new accounts a day); keeping the key out of JavaScript strings, which needs native signing (F47); clock skew past a day when the other device is slow (F36); and the step-5 case of a save from a newer Kefli arriving under S during the move.
- **Code the gate doesn't score:** over complexity 10 in files `.code-gate.json` leaves out, `runner.ts` `run` (16), `voice.ts` `listen` (18), `ShareRoot.tsx` `row` (21) and its save callback (14), `pickup.ts` `asWritten` (11), `Advanced` (18) and the extension's `capture.ts` `sizeOf` (12); functions lizard reads only in part or not at all, `watch` and `close` in `net/pool.ts`, `stagedBlob` and `copyAll` in `services/move.ts`, `partition` in `services/sync.ts`, `browserName` in `data/inbox.ts` (its regex literal), and the extension's generic `exclusive`, `changeQueue` (scored under the name "exclusive"), `sealedOnly`, `orAfter` and `store.ts`'s `get`, since lizard skips a function with type parameters; and `apps/mobile/jest.config.js` collects no coverage from `services/inbox.ts` or `services/move.ts`, so a coverage run of the app alone scores them wrongly, where the root run is right.

Commits to `main` go through the code-gate CRAP check (CLAUDE.md, Rules). On this laptop it ran as a git pre-commit hook from Claude's code-gate skill; a new machine needs the hook installed again before the first commit. The gate reads `coverage/lcov.info` (`.code-gate.json`), which `npm run coverage` writes with the Go suite's lines appended, so refresh it that way rather than with Jest alone. The gate's parser, lizard, misreads some regex literals (with escaped slashes or a backtick, and a few plainer ones such as `/^[a-z-]+:/`), a template holding quotes, a default parameter that calls a function, a ternary of object literals holding templates, a parameter typed as an arrow function, type parameters (`function f<T>`), a union written as a return type, a type declared just after a function, a cast or a `??` of a bracketed `await`, an optional call (`?.(`), and a spread of an awaited value or a ternary inside an object literal: it stops scoring the functions after it, scores them a line out or over another's lines, or drops them, and still passes. Write such a pattern as `new RegExp('…')` or a plain string, name the type, read the value into a variable first, and check a changed file's functions and their lines with `python3 -m lizard <file>`. lizard reads no Kotlin expression body, so the native modules' functions are written with block bodies, and it counts each `??` as two branches. The Makefile runs Go in Docker with the whole repository mounted, since the Go tests read `shared/fixtures`, and hands fresh cache volumes to the calling user first, as on a CI runner.
