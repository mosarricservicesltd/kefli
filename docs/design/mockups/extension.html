Kefli prototype · batch 5 · browser extension · Fingerprint

Click the Kefli button in the toolbar or press Alt+Shift+S to save the page, or jump to any state below. The toast never takes focus: press the shortcut again while it says Saved to reach Undo, then Tab, Escape or ✕ to go back to the page. It pauses while the pointer is over it or focus you gave it is inside it. On a browser page, a small popup opens under Kefli’s button instead. Kefli’s options open in their own tab; click the article’s tab to go back. When Kefli isn’t pinned, click the puzzle piece to pin it. The browser window, tab strip, badge and right-click menu are Chrome’s, drawn only for context; the toast, the popup and the options page are Kefli’s. Decisions and build notes are under the window.

Every save wears its cover, drawn by cover v1 from the sha256 of its normalised address, so the Atlantic article has the same face here, on the board and on the phone. The options page and the popup use Archivo: the extension bundles it as local font files, because its content security policy blocks remote fonts, while this mockup loads it from Google Fonts. The injected toast keeps system-ui.

Settled (decision 31): a ninth save made offline while eight are waiting is refused with a clear message, so nothing you saved is ever silently lost. Spec 05 says the same.

Changed in this pass (Fingerprint, decisions 65 to 67 and 70): the look only; flows, copy, controls and behaviour are as before. The toast’s leading circle becomes the saved page’s cover, drawing itself while Kefli saves, and a small mark on its corner says what happened: a tick once it is saved, the offline mark while it waits to send, the alert mark when it couldn’t send. A removed or refused save shows a plain tile the same size, since there is no save to show. The countdown runs in the article’s ink, chosen for 3:1 on the toast. Saves listed under Couldn’t send wear their covers too. Fills are ink on paper, or paper on ink in dark, with the page colour on them; there is no Terracotta and no gradient. The toolbar button, tab, address bar, menu and options logo show the app icon Richard chose (decision 70): C·L·063 with the paper mark, a paper bookmark and bar in an ink outline on orange bands and cream, with its own drawings for 16, 28 and 32 px. The badge stays neutral grey (decision 64).

Motion (decision 73, motion-spec.md): the toast rises 24 px as it fades in and sinks by the exact reverse; a second save, Saving… becoming Saved, and Undo change it in place by crossfade. The cover draws itself once in the leading slot, and its corner mark lands with the last leaf, never more than a second in. The countdown runs by transform. The popup has no entrance of its own, since the browser opens it, but its cover draws as in the toast. On the options page, Retry turns busy at the tap and shows its dots after 150 ms; a sent row holds Sent for 1.5 s, then leaves and the rows below close the gap. Advanced, the Disconnect confirm and an expired code crossfade, Connected swaps the page, and the pin hint leaves like a row. With reduced motion everything fades in place and nothing travels; the countdown keeps running.

Earlier pass (decisions 57 to 64): the toast never takes focus; a second press of the shortcut reaches Undo (58, updates 44). Browser pages show a small popup as well as the tick (59). Offline saves offer Undo (60, changes 30). The badge, the button’s name and the options notice count offline saves only (30); saves that couldn’t send are listed on the options page. Disconnecting names every unsent save it would delete, including ones that couldn’t send.

Build notes
  • Toast: the shadow-root contract is in the comment above the toast host in this file’s source.
  • Motion: the toast’s rise and sink are CSS transitions on transform and opacity with @starting-style, declared on the inner toast with the motion tokens as custom properties, so a sink interrupted by a new save turns round from where it is. The countdown is a full-width fill translated left in a clipped strip, held with animation-play-state. Put ShelfCover.css and the reduced-motion rules in each shadow root. On the options page, neighbours move by FLIP through the Web Animations API, a group’s surface is drawn per row so its edge can glide, and nothing animates height.
  • Covers: bundle shared/cover/cover-v1.js (frozen) in the toast script, the popup and the options page. The background already computes each save’s d-tag hash (contract 4.3) and sends it with the result. The toast draws ShelfCover.svg(hash, {draw: true}), keeps the same cover element when Saving… becomes Saved so the drawing isn’t restarted, and brings the corner mark in as the last leaf lands (520 ms plus 34 ms a leaf), or at 1 s if the drawing is longer (motion spec, Before build item 4). Covers in the Couldn’t send list are drawn still. The toast’s countdown takes ShelfCover.lineInk(hash, surface, text) for the toast’s colours, the popup’s for its surface.
  • Icon: decision 94’s icons, built from shared/brand/src into shared/brand/out/extension/. The manifest’s icons and action.default_icon take icon-16.png and icon-32.png, the toolbar button (the plain bookmark, toolbar-16.svg and toolbar-32.svg), and icon-48.png and icon-128.png, the app icon D (small-48.svg, and the 108 dp drawing with the Web Store’s padding); Firefox takes icon-16.svg and icon-32.svg for its 16 and 32 keys. Chrome picks the size for the screen, 16 on a 1x screen and 32 drawn at 16 on anything denser, and this mockup does the same. The options page’s 28 px logo inlines options-logo-28.svg, D’s tuned 28 px cut built from small-28.svg. It is static artwork.
  • Second press: while a Saved toast shows, the command handler asks the tab’s content script to reach Undo and passes the keyboard flag.
  • Install: on runtime.onInstalled with reason 'install', call runtime.openOptionsPage() so Connect opens by itself. The Firefox manifest overlay sets action.default_area:'navbar'.
  • Pin line: read action.getUserSettings().isOnToolbar (Chrome 91+, Firefox 118+); re-check on focus, visibilitychange and action.onUserSettingsChanged where it exists, and drop the line once Kefli is pinned.
  • Browser-page popup: in the command or click handler, action.setPopup({popup:'saved.html'}), then action.openPopup(), then setPopup({popup:''}) so the next click still saves. Needs Chrome 127+; below that the tick alone stays. Firefox allows openPopup() from the same user-action handler.
  • Badge: setBadgeBackgroundColor '#5C5B56' (the light muted grey) while saves wait to send and '#1E7A4A' (the light success green, tokens 0.2.1) for the tick; setBadgeTextColor('#F3F2EE') in both builds.
  • Shortcut: read the live binding with commands.getAll() in both browsers. 'Set a shortcut' opens chrome://extensions/shortcuts with tabs.create (Edge and Brave redirect it); in Firefox, commands.openShortcutSettings() where it exists, otherwise the words 'Add-ons, then the gear, then Manage Extension Shortcuts'. In this mock it simulates setting Alt+Shift+S there and coming back.
  • Fonts: the options page and the popup use Archivo (Archivo Expanded, width 125, for the titles and the wordmark), bundled as local @font-face files, because the extension’s content security policy blocks remote fonts. Ship the static cuts the board lists (Regular, Medium, SemiBold, Expanded Bold). This mockup loads them from Google Fonts through tokens.css. The injected toast stays system-ui.
  • Browser name: the connected lead takes it from the pairing label; fall back to navigator.userAgent where navigator.userAgentData is missing (Firefox).
  • Firefox build: the menu item is titled 'Save Link to Kefli' (Title Case) and the options row repeats that wording; the options page lives at moz-extension://…/options.html; a save from about:reader?url=… sends the inner url. No Firefox window is drawn here.
  • Check: verify in a light and a dark Windows contrast theme (for example Desert and Night sky).
