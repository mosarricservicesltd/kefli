Shelf prototype · batch 5 · browser extension

Click the Shelf button in the toolbar or press Alt+Shift+S to save the page, or jump to any state below. The toast never takes focus: press the shortcut again while it says Saved to reach Undo, then Tab, Escape or ✕ to go back to the page. It pauses while the pointer is over it or focus you gave it is inside it. On a browser page, a small popup opens under Shelf’s button instead. Shelf’s options open in their own tab; click the article’s tab to go back. When Shelf isn’t pinned, click the puzzle piece to pin it. The browser window, tab strip, badge and right-click menu are Chrome’s, drawn only for context; the toast, the popup and the options page are Shelf’s. Decisions and build notes are under the window.

For you to decide: the spec drops the oldest queued save when a ninth is made offline. Here the ninth is refused instead, with a clear message, so nothing you saved is ever silently lost (decision 31).

Changed in this pass: the toast never takes focus; a second press of the shortcut reaches Undo (58, updates 44). Browser pages show a small popup as well as the tick (59). Offline saves offer Undo (60, changes 30). The badge, the button’s name and the options notice count offline saves only (30); saves that couldn’t send are listed on the options page. Disconnecting names every unsent save it would delete, including ones that couldn’t send.

Build notes
  • Toast: the shadow-root contract is in the comment above the toast host in this file’s source.
  • Second press: while a Saved toast shows, the command handler asks the tab’s content script to reach Undo and passes the keyboard flag.
  • Install: on runtime.onInstalled with reason 'install', call runtime.openOptionsPage() so Connect opens by itself. The Firefox manifest overlay sets action.default_area:'navbar'.
  • Pin line: read action.getUserSettings().isOnToolbar (Chrome 91+, Firefox 118+); re-check on focus, visibilitychange and action.onUserSettingsChanged where it exists, and drop the line once Shelf is pinned.
  • Browser-page popup: in the command or click handler, action.setPopup({popup:'saved.html'}), then action.openPopup(), then setPopup({popup:''}) so the next click still saves. Needs Chrome 127+; below that the tick alone stays. Firefox allows openPopup() from the same user-action handler.
  • Badge: setBadgeBackgroundColor '#535862' while saves wait to send and '#079455' for the tick; setBadgeTextColor('#FFFFFF') in both builds.
  • Shortcut: read the live binding with commands.getAll() in both browsers. 'Set a shortcut' opens chrome://extensions/shortcuts with tabs.create (Edge and Brave redirect it); in Firefox, commands.openShortcutSettings() where it exists, otherwise the words 'Add-ons, then the gear, then Manage Extension Shortcuts'. In this mock it simulates setting Alt+Shift+S there and coming back.
  • Fonts: the options page and the popup use Inter, bundled as a local @font-face (the extension’s CSP forbids remote fonts). The injected toast stays system-ui.
  • Browser name: the connected lead takes it from the pairing label; fall back to navigator.userAgent where navigator.userAgentData is missing (Firefox).
  • Firefox build: the menu item is titled 'Save Link to Shelf' (Title Case) and the options row repeats that wording; the options page lives at moz-extension://…/options.html; a save from about:reader?url=… sends the inner url. No Firefox window is drawn here.
  • Check: verify in a light and a dark Windows contrast theme (for example Desert and Night sky).
