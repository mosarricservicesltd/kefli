Core loop

The user opens the app to read what they saved earlier.

Listening is a way of reading, not a second job. Saving is how things get in. Every screen either serves this sentence or carries a written reason below.

Screen a place the user lands Action tap, swipe, gesture Input typed, chosen, scanned Decision a fork the user resolves Wait blocks the user Silent the app works without asking Permission an OS prompt ★ Value first value

Navigation

Three tabs, bottom bar: Saves (the core loop, where the app opens), Listen, You. Stack navigation inside each tab; Android back always pops one level and never exits from a deep screen. The mini player docks above the tab bar on every tab while audio is loaded. No drawer, no Home or discovery tab, no notifications. Each tab keeps its own scroll position when you switch away and back (decision 74).

Entry points
  • Cold open, first launch → launch screen (up to 5 s, a tap skips it) → Welcome new · 97
  • Cold open after a reinstall, with a key in Block Store → Saves with the restore card, never Welcome changed · 79
  • Share sheet from any app, including before the first open new
  • Returning open → where the user was new
  • Lock screen or media notification → Reader at the spoken word new
  • Browser extension toolbar, shortcut or right-click (desktop)
Returning open rule new
  • Last screen was the Reader, less than 12 hours ago → Reader at the saved position
  • Anything else → Saves
  • Back from the Reader always goes to Saves

1 · First launch

No signup, no tour. One question, then the empty state does the teaching.

  1. Screen
    Welcome new. App name, one line on what it does, two buttons: New here (primary) and I already have a library.
  2. Decision
    New here → continue below. I already have a library → journey 2.
  3. Silent
    Generate key, store in Keystore, back up through Google Block Store. No screen.
  4. Screen
    Saves, empty. Teaches the share sheet with one illustration of it. One button: Connect your browser. The nostr sign-in link has moved to journey 2. Offline, the notice slot reads “Connecting a browser needs a connection” and the button is disabled (saves-empty-offline) new · 91 (g).
  5. Action
    In any app: Share → Kefli. (Journey 3.)
  6. Screen
    Saved sheet → Read now
  7. Screen
    Reader, clean text ★ FIRST VALUE

Share before the first open new

  1. Action
    Freshly installed, never opened: Share → Kefli.
  2. Silent
    Key generated as above, unless Block Store already holds a key: then the share stores that key and saves under it, and the next open goes to Saves with the restore card (below) changed · 79. The save proceeds normally.
  3. Screen
    Saved sheet → Read now → Reader ★
  4. Screen
    On the first proper open: Welcome. New here → Saves, already populated. I already have a library → journey 2, and the early saves are moved into the restored library, never lost. The note under Welcome shows the newest early save’s cover and counts them: “You’ve already saved one article. It’ll be in your library either way.”, or for several, “You’ve already saved three articles. They’ll be in your library either way.” (welcome-early-many) new · 91 (f); the restore card adds “Your three saves from before are included.”

Reinstalling where Block Store holds a key changed · 79

  1. Action
    Kefli reinstalled on a phone whose Google Backup kept Block Store’s entry; first open.
  2. Silent
    No key on the phone, and Block Store holds a recovery phrase: Kefli stores that key, marks the first-launch question answered and starts the restore. No screen.
  3. Screen
    Saves with the restore card (journey 2’s Restoring); Welcome and its question never show. If the restore finds nothing, first-run Saves with no card (restore-nothing) new · 91 (a).
  4. Unhappy
    Google Backup off: the entry doesn’t survive the reinstall, so Welcome opens as on a new phone and the way back is journey 2. A share before this first open reads Block Store first and saves under the same key, so it isn’t an early share and nothing needs moving.

2 · Returning to a library new

A new phone, a reinstall without Google backup, or an existing nostr user. Every way back in sits on one screen.

  1. Screen
    Bring back your library. Three rows: Scan from my other phone, Enter my recovery code, Sign in with your nostr app. Back returns to Welcome.
  2. Decision
    Which of the three.
  3. Screen
    A · Scan from my other phone. One line: "On your other phone, open You, then Add another device."
    1. Permission
      Camera, asked here and only here, with the reason on screen first.
    2. Input
      Scan the QR, then type the six-digit code shown on the other phone. The code is a second factor, never an alternative to scanning (decision 53).
    3. Wait
      Connecting. An online exchange: the other phone has posted the twelve words to Kefli’s server, encrypted under the QR’s secret and the six digits; this phone fetches them with a throwaway key, checks them against the QR and stores the library. The server holds the offer for five minutes and limits tries, so a photo of the QR can’t be tested offline against every code changed · 85.
    4. Unhappy
      Camera refused → screen explains; the way on is the recovery code, or Android settings to turn the camera on (decision 53). Code expired → "That code has expired. Show a new one on your other phone."
  4. Screen
    B · Enter my recovery code. Twelve numbered fields; paste fills all twelve; each word autocompletes from the standard list. Numbered down the first column, 1 to 6, then the second, 7 to 12. A word fills itself in, and the next field takes over, as soon as the letters typed fit only one word (two letters for a few, four at most); words that begin others, such as “act”, end with a space or a suggestion. The rest of a word typed on after it filled in is swallowed once, not carried into the next field changed · 106.
    1. Input
      Twelve words.
    2. Unhappy
      A word not on the list is marked at that field. A valid code with nothing saved under it: "No saves found for this code" with Try again and Start fresh instead.
  5. Screen
    C · Sign in with your nostr app. Hands off to the signer app on the phone (NIP-55), with a remote signer (NIP-46) as the second choice. "nostr" appears on this route, on switching to a nostr app, on You for nostr users and on the deletion route, and nowhere else changed · 86. A Keep backup copies switch, on by default, adds Kefli’s server and one independent backup to the user’s own server list (contract 3.1, decision 76) new.
    1. Unhappy
      No signer app installed → a short explanation and the remote-signer option. Request refused in the signer → back to this screen, nothing changed.
    2. Unhappy
      A remote signer that doesn’t answer within two minutes, or answers with a timeout → back to the start, with “Your nostr app didn’t answer. Nothing has changed.” in the notice slot (nostr-timeout). A sign-in link that’s malformed or can’t be reached → at the field, link kept: “That link didn’t work. Copy it again from your nostr app.” (nostr-badlink) new · 91 (b). The app fails the privacy check (it can’t encrypt to itself) → back to the start with “Your nostr app can’t keep your saves private yet. Try another app, or start a new library on this phone.” and Start a new library under Open my nostr app, which goes where New here goes, to first-run Saves, empty (nostr-probe) new · 91 (d).
    3. Silent
      Right after a sign-in with a nostr app on the phone, during “Waiting for your nostr app”, Kefli checks that the app will sign everything saving does out of sight without asking (the save, deletions, the relay and server lists, relay and API sign-in, the backup uploads, a browser’s seal). All allowed → nothing more. Anything missing → Save without asking: “Your nostr app asks you to approve each save before Kefli can back it up. Approve once now and choose to remember it, and saving from any app needs nothing more from you.” Open my nostr app sends one request per missing kind (“Request 1 of 3”); Ask me each time or Back goes on, and saving still works with backups waiting for approval. Still asking after approval, or declined → the notice line with Try again. A sign-in link (remote signer) isn’t checked new · 104.
    4. Decision
      Once, after first sign-in, and only when the person’s lists hold web links that aren’t saves yet: “Bring in your bookmarks?” Web links only: kind 39701 web bookmarks and any legacy r tags in their 10003 list and 30003 sets; notes, long-form articles and private entries aren’t imported. The count is the links found, saved ones skipped, worded for one or several (“We found one bookmark…”, “We found 23 bookmarks…”) changed · 82 new · 91 (f). Private by default, no cap. Either answer starts the restore; imported links join after its first pass as pending rows.
  6. Wait
    Restoring. Saves fill in as they arrive from the three relays; text downloads from mirrored storage. The list is usable at once (partial state). One line says this works even if Kefli's own server is off, in plain words.
  7. Unhappy
    Nothing to bring back: a nostr sign-in, a Block Store restore or a pairing that finds no saves lands on first-run Saves, empty (journey 1), with no restore card (restore-nothing) new · 91 (a). A recovery code that finds nothing keeps “No saves found for this code”.
  8. Screen
    Saves, populated ★

3 · Save from the phone

  1. Action
    Share → Kefli, from any app.
  2. Screen
    Saved sheet, confirmed at once: title, source, "Private. Ready to read offline in a moment." Undo · Read now. Dismisses itself after 4 seconds and returns the user to the app they were in.
  3. Silent
    Fetch and parse; cache the text; encrypt; publish to three relays; queued if offline. An article's pictures are fetched when it is first read, and kept for reading offline after that changed · 114.
  4. Screen
    Already saved. Sharing a link that is already in the library and unread changes nothing: the sheet reads “Already in your library” and “Still in Unread, where you left it.” with Done and Read now, and no Undo, since there is nothing to undo (share-again) new · 89, G2. An archived save shared again comes back to Unread at its new save time, on the usual sheet, whose Undo archives it again.
  5. Silent
    A linked PDF is read for its text on the phone and saved like a page: headings, paragraphs and lists, without running headers, page numbers, footnote marks, tables, charts or equations. A PDF that is only pictures of pages, or is locked with a password, is saved as a link; opening it shows the original under a notice saying which (“This PDF is pictures of pages, with no text to read or listen to, so here’s the original.”) new · 103.
  6. Screen
    A shared X post is checked first: the sheet reads "Checking the post" while Kefli reads it through X’s public embed service to find the first link leading outside X, then saves that article as usual. Nothing of X’s is stored (decisions 77 and 78) new. If X’s embed service doesn’t answer while the phone is online, the post’s address is saved as pending and checked again from 30 seconds, doubling to an hour: the sheet reads “Saved · will check the post when X answers” with Undo and Done (share-embedfail), the row “Will check the post when X answers” with the hourglass (saves-embedfail), and opening it says “Kefli will check this post when X answers. If it links to an article, the article will be here to read, offline too.” changed · 89, G3. Once checked it goes on as an offline post does.
  7. Unhappy
    Offline → sheet reads "Saved · will fetch when online". Shared text with no link → "That wasn't a link." Page can't be parsed → saved as a link; the row later reads "Couldn't get the text · open original". A page Readability marks not readable, with very little text, such as a sign-in wall, counts as one that can't be parsed (decision 77). An X post with no link outside X, or one pointing to an X Article → "No article in that post", nothing saved; offline, it is saved and checked later, and reads "Couldn't get the text · open original" if it has no article (decision 78).

4 · Save from the browser

Connecting a browser (once)

  1. Action
    Laptop: install the extension and click its icon. Unpaired, so the options page opens.
  2. Screen
    Extension: connect. QR, a short typed code under it new, a five-minute countdown, and "Open Kefli on your phone, go to You, then Connect a browser."
  3. Action
    Phone: You → Connected browsers → Connect a browser.
  4. Permission
    Camera, first time only, reason shown first.
  5. Input
    Scan the QR, or Type a code instead new.
  6. Screen
    Connect this browser? "Chrome on a Windows PC". One tap.
  7. Screen
    Phone returns to Connected browsers with the new row. Extension shows "Connected to your phone" and the date.
  8. Unhappy
    Code expired → "This code expired" with Show a new one. No connection → "Can't connect right now. Check your connection." and a retry every ten seconds. Camera refused → the typed code.

Every save after that

  1. Action
    Toolbar icon, keyboard shortcut, or right-click → Save link.
  2. Screen
    Toast: "Saving…" then "Saved to Kefli · Undo", eight seconds. Open in app is removed new.
  3. Unhappy
    No text captured → "Saved — your phone will fetch the text". Offline → "Saved — will send when you're online", no Undo. Eight waiting → "8 waiting". Pages where scripts can't run → a tick on the icon for four seconds, link only.
  4. Silent
    Phone picks it up next time the app is open; until then it shows as a pending row.

5 · Read

  1. Screen
    Saves: Unread, newest first. Row: source · title · read time · audio mark if audio is downloaded. Search at the top. Unread / Archive switch.
  2. Action
    Tap a row → Reader. Swipe left → Archive, with a five-second undo.
  3. Screen
    Reader. Progress line. Top bar: back · ▶ · Speed read · Aa · ⋯ (Delete new, Open original, Copy link). Speed read has its own button before Aa, shown once the text is there, and leaves the ⋯ menu new · 110.
  4. Action
    Reach the end → End card: Archive · Next unread. Delete → back to Saves with a five-second undo new.
  5. Screen
    Original page. ⋯ → Open original, and a save whose text couldn’t be fetched, open the page in Kefli’s own view: the page under Kefli’s bar (✕, title and host, ⋯ with Open in browser, Copy link and Delete) and the floating Archive. Open in browser covers sites where the person is signed in changed · 81.
    1. Wait
      Loading: the Reader’s skeleton under the bar (reader-original-loading) new · 81.
    2. Unhappy
      An HTTP or TLS error, or a site that refuses to open in an app → “This page won’t load here. Your browser may still open it.” with Open in browser (reader-original-failed) new · 81. Offline → “Opening the original needs a connection” (reader-original-offline) new · 89, G4.
  6. Screen
    Aa sheet. Text size, and Light · Sepia · Dark for the Reader.
  7. Screen
    Archive. Same rows. Swipe right → back to Unread. Swipe left → Delete, on the error fill, with a five-second undo new · 112. Both also in each row's ⋯.
  8. Screen
    Search. On-device, full text, across Unread and Archive, results labelled with which list they're in.

6 · Listen

  1. Action
    ▶ in the Reader.
  2. Screen
    The phone's voice starts at once; words highlight as they're spoken; the mini player docks (play/pause, skip ±15 s, speed). The article joins the Listen tab.
  3. Action
    Double-tap a word in the Reader: the voice plays from it, moving there if the article is playing, or starting there if not. Speed steps 1×, 1.5×, 2×, 0.5× new · 107.
  4. Unhappy
    A voice that reports no word positions: the whole sentence is marked instead, the progress line moves across each sentence’s estimated time, and Now playing’s word meter stays unlit (play-sentence) new · 91 (h). Speed read is unaffected.
  5. Silent
    Citation markers ([1], “[citation needed]”), numbered footnote links and a Wikipedia article’s reference list are skipped by the voice; the Reader still shows them new · 102.
  6. Silent
    Ask the server for the better voice. It's cached per article and used from the next play; it never swaps voices mid-article.
  7. Screen
    Lock screen and car controls. Tap → Reader at the spoken word new.
  8. Screen
    Listen tab: the Now playing card, always there: with no session it holds the last played article still in Unread (or the top of Unread) ready to play at its position, and ✕ returns it to that. Then Unread, newest first, the saves that have their text changed · 111. Play all continues down that list from the top; it's the only auto-continue.
    1. Action
      A row's body puts its article in the card, ready at its place ("Up next"); anything playing stops with its place kept, and the list scrolls back to the card if it was scrolled away (listen-cued). The cover still plays at once; the card's title opens the Reader new · 115.
    2. Action
      The card's ruler seeks: tap a point to jump there, or drag along it, a knob and the time following, and let go (listen-scrub). Playing goes on from there; paused stays paused; the ready card's stored place moves new · 115.
  9. Unhappy
    Better voice unavailable for an article → a quiet note; the phone's voice carries on. Offline → downloaded audio plays, everything else uses the phone's voice.

7 · You

  1. Screen
    You. Header: nostr name and picture if signed in with a nostr app, otherwise "47 saves · 12 listened" new. Then: Back up your library card (while not done), Recovery code, Add another device, Connected browsers, Voice, Advanced, Delete my data. Signed in with a nostr app: “Your nostr app · Signed in” in place of the card and the Recovery code row, stamped “Asks before each save” while the app won’t sign saves without asking; sign-ins made before decision 104 are checked in the background at most once a day and only the row changes changed · 104. The row opens Your nostr app: signed in with the app (or “A sign-in link”), Saving “Without asking” or stamped “Asks before each save” with Save without asking as the screen’s action, and Sign out as a red row. Sign out asks first in a sheet, “Sign out?”: “Kefli removes your library from this phone. Your saves stay under your key, and signing in with your nostr app again brings them back. You can remove Kefli in your nostr app too.”, naming saves not yet sent. It clears the library and the signer from this phone only, keeps reader and voice settings, and returns to Welcome with “You’re signed out” new · 105, and no Add another device, since there are no twelve words on the phone to pass on; a second phone signs in with the nostr app instead (you-nostr) changed · 90.
  2. Screen
    Recovery code sheet. Twelve numbered words, down the first column and then the second changed · 106, Copy, one line on when you'd need it. Viewing it clears "Not written down".
  3. Screen
    Add another device. QR plus six-digit code, five minutes. Expired → "Code expired, show a new one". Showing the QR posts the online exchange that journey 2’s Connecting fetches changed · 85.
  4. Screen
    Connected browsers. List, Connect a browser, Disconnect with its dialog: "Pages saved from that browser will be ignored. Uninstall the extension there or connect it again."
  5. Screen
    Voice. The phone's voices, one choice per language: chips for the phone's language and each language among the saves, the chosen chip's voices as radios with samples, Default speed changed · 109.
  6. Screen
    Advanced. Relays (the one place the word appears), Export, Use my nostr app instead new, which moves every save across, with the same Keep backup copies switch (decision 76).
    1. Action
      Add a relay ends the Relays group, disabled offline with “Needs a connection”, and opens its own screen: one Relay address field and Add relay, which shows “Checking the relay” while Kefli connects and offers the relay the person’s newest relay list, already signed. Each problem is a field error with the address kept: not a relay address (adv-add-bad), already copied to, didn’t answer (adv-add-unreachable), won’t take saves (adv-add-refused); offline, the banner and a disabled button (adv-add-offline). Taken, Advanced returns with “Copying your saves to relay.example.org” and the saves are copied in the background (adv-add-checking). It shows as Your relay, counted in the note, and its row asks “Remove this relay?” with a red Remove (adv-mine, adv-remove); Kefli’s relay and the backups can’t be removed new · 113.
    2. Silent
      Saves no backup server holds yet are counted in the notice slot, while there are any: “Two saves aren’t backed up yet. Kefli keeps trying until a backup server accepts them.” (adv-notbacked) new · 93. Meanwhile the note under the relays reads “Your other saves are copied to all three.” A save is backed up once a relay Kefli doesn’t run has accepted its newest change and, for a save with text, a mirror holds its text.
    3. Unhappy
      Export my saves writes kefli-export.html to Downloads, offline too. If it fails: “The export didn’t save. Check the phone has space, then try again.” with Try again (adv-exportfail) changed · 89, G9.
    4. Unhappy
      Use my nostr app instead with no nostr app on the phone → the sign-in’s “No nostr app on this phone”, with the sign-in link field (sw-none). The app fails the privacy check → “Your nostr app can’t keep your saves private yet. Try another app. Nothing has changed.” (sw-probe) new · 91 (c). A save from a newer Kefli, met while gathering either library, stops the move before any save is copied: “Some saves come from a newer version of Kefli. Update Kefli, then try again.” and “Your saves are still on this phone, and your recovery code still works.”, with Update Kefli; the nostr app’s registration and server lists stay (sw-newer) new · 91 (i).
  7. Screen
    Delete my data. What goes, and what can only be asked of independent relays. Type DELETE to confirm new. Done → Welcome. The explain screen says “This removes your library from all your devices and from Kefli’s server.” and counts the backup servers from the person’s real lists, the mirror and a nostr user’s own servers included (“Copies on three independent backup servers”; for a nostr user, “Copies on four other servers”, two of them their own). Deleting shows a step for each server, Kefli’s first and this phone last, and names any that didn’t confirm (del to del-failed) changed · 91 (e).

Screen inventory for the mockups

Built locally as HTML prototypes, phone-sized (360 × 800, checked at 412 × 915), light and dark, each state from the matrix as its own frame. Batches, in order:

  1. Core loop: Saves (all states), Saved sheet, Reader (all states), Aa sheet, end card.
  2. Listen: mini player, Reader playing with highlight, Listen tab, lock screen reference.
  3. First launch and return: Welcome, Bring back your library, scan, recovery code, nostr sign-in, Restoring.
  4. You: You, recovery code sheet, Add another device, Connected browsers and Connect this browser?, Voice, Advanced, Delete my data.
  5. Extension: toast states, options page states.
