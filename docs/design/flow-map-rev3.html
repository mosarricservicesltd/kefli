Core loop

The user opens the app to read what they saved earlier.

Listening is a way of reading, not a second job. Saving is how things get in. Every screen either serves this sentence or carries a written reason below.

Screen a place the user lands Action tap, swipe, gesture Input typed, chosen, scanned Decision a fork the user resolves Wait blocks the user Silent the app works without asking Permission an OS prompt ★ Value first value

Navigation

Three tabs, bottom bar: Saves (the core loop, where the app opens), Listen, You. Stack navigation inside each tab; Android back always pops one level and never exits from a deep screen. The mini player docks above the tab bar on every tab while audio is loaded. No drawer, no Home or discovery tab, no notifications. Each tab keeps its own scroll position when you switch away and back (decision 74).

Entry points
  • Cold open, first launch → Welcome
  • Share sheet from any app, including before the first open new
  • Returning open → where the user was new
  • Lock screen or media notification → Reader at the spoken word new
  • Browser extension toolbar, shortcut or right-click (desktop)
Returning open rule new
  • Last screen was the Reader, less than 12 hours ago → Reader at the saved position
  • Anything else → Saves
  • Back from the Reader always goes to Saves

1 · First launch

No signup, no tour. One question, then the empty state does the teaching.

  1. Screen
    Welcome new. App name, one line on what it does, two buttons: New here (primary) and I already have a shelf.
  2. Decision
    New here → continue below. I already have a shelf → journey 2.
  3. Silent
    Generate key, store in Keystore, back up through Google Block Store. No screen.
  4. Screen
    Saves, empty. Teaches the share sheet with one illustration of it. One button: Connect your browser. The nostr sign-in link has moved to journey 2.
  5. Action
    In any app: Share → Shelf. (Journey 3.)
  6. Screen
    Saved sheet → Read now
  7. Screen
    Reader, clean text ★ FIRST VALUE

Share before the first open new

  1. Action
    Freshly installed, never opened: Share → Shelf.
  2. Silent
    Key generated as above; the save proceeds normally.
  3. Screen
    Saved sheet → Read now → Reader ★
  4. Screen
    On the first proper open: Welcome. New here → Saves, already populated. I already have a shelf → journey 2, and the early saves are moved into the restored shelf, never lost.

2 · Returning to a shelf new

A new phone, a reinstall without Google backup, or an existing nostr user. Every way back in sits on one screen.

  1. Screen
    Bring back your shelf. Three rows: Scan from my other phone, Enter my recovery code, Sign in with your nostr app. Back returns to Welcome.
  2. Decision
    Which of the three.
  3. Screen
    A · Scan from my other phone. One line: "On your other phone, open You, then Add another device."
    1. Permission
      Camera, asked here and only here, with the reason on screen first.
    2. Input
      Scan the QR, then type the six-digit code shown on the other phone. The code is a second factor, never an alternative to scanning (decision 53).
    3. Unhappy
      Camera refused → screen explains; the way on is the recovery code, or Android settings to turn the camera on (decision 53). Code expired → "That code has expired. Show a new one on your other phone."
  4. Screen
    B · Enter my recovery code. Twelve numbered fields; paste fills all twelve; each word autocompletes from the standard list.
    1. Input
      Twelve words.
    2. Unhappy
      A word not on the list is marked at that field. A valid code with nothing saved under it: "No saves found for this code" with Try again and Start fresh instead.
  5. Screen
    C · Sign in with your nostr app. Hands off to the signer app on the phone (NIP-55), with a remote signer (NIP-46) as the second choice. The only screen that says "nostr". A Keep backup copies switch, on by default, adds Shelf’s server and one independent backup to the user’s own server list (contract 3.1, decision 76) new.
    1. Unhappy
      No signer app installed → a short explanation and the remote-signer option. Request refused in the signer → back to this screen, nothing changed.
    2. Decision
      Once, after first sign-in: "Bring in your existing bookmarks?" Private by default. Skippable.
  6. Wait
    Restoring. Saves fill in as they arrive from the three relays; text downloads from mirrored storage. The list is usable at once (partial state). One line says this works even if Shelf's own server is off, in plain words.
  7. Screen
    Saves, populated ★

3 · Save from the phone

  1. Action
    Share → Shelf, from any app.
  2. Screen
    Saved sheet, confirmed at once: title, source, "Private. Ready to read offline in a moment." Undo · Read now. Dismisses itself after 4 seconds and returns the user to the app they were in.
  3. Silent
    Fetch and parse; cache text and images; encrypt; publish to three relays; queued if offline.
  4. Screen
    A shared X post is checked first: the sheet reads "Checking the post" while Shelf reads it through X’s public embed service to find the first link leading outside X, then saves that article as usual. Nothing of X’s is stored (decisions 77 and 78) new.
  5. Unhappy
    Offline → sheet reads "Saved · will fetch when online". Shared text with no link → "That wasn't a link." Page can't be parsed → saved as a link; the row later reads "Couldn't get the text · open original". A page Readability marks not readable, with very little text, such as a sign-in wall, counts as one that can't be parsed (decision 77). An X post with no link outside X, or one pointing to an X Article → "No article in that post", nothing saved; offline, it is saved and checked later, and reads "Couldn't get the text · open original" if it has no article (decision 78).

4 · Save from the browser

Connecting a browser (once)

  1. Action
    Laptop: install the extension and click its icon. Unpaired, so the options page opens.
  2. Screen
    Extension: connect. QR, a short typed code under it new, a five-minute countdown, and "Open Shelf on your phone, go to You, then Connect a browser."
  3. Action
    Phone: You → Connected browsers → Connect a browser.
  4. Permission
    Camera, first time only, reason shown first.
  5. Input
    Scan the QR, or Type a code instead new.
  6. Screen
    Connect this browser? "Chrome on a Windows laptop". One tap.
  7. Screen
    Phone returns to Connected browsers with the new row. Extension shows "Connected to your phone" and the date.
  8. Unhappy
    Code expired → "This code expired" with Show a new one. No connection → "Can't connect right now. Check your connection." and a retry every ten seconds. Camera refused → the typed code.

Every save after that

  1. Action
    Toolbar icon, keyboard shortcut, or right-click → Save link.
  2. Screen
    Toast: "Saving…" then "Saved to Shelf · Undo", eight seconds. Open in app is removed new.
  3. Unhappy
    No text captured → "Saved — your phone will fetch the text". Offline → "Saved — will send when you're online", no Undo. Eight waiting → "8 waiting". Pages where scripts can't run → a tick on the icon for four seconds, link only.
  4. Silent
    Phone picks it up next time the app is open; until then it shows as a pending row.

5 · Read

  1. Screen
    Saves: Unread, newest first. Row: source · title · read time · audio mark if audio is downloaded. Search at the top. Unread / Archive switch.
  2. Action
    Tap a row → Reader. Swipe left → Archive, with a five-second undo.
  3. Screen
    Reader. Progress line. Top bar: back · Aa · ▶ · Archive · ⋯ (Delete new, Open original, Copy link).
  4. Action
    Reach the end → End card: Archive · Next unread. Delete → back to Saves with a five-second undo new.
  5. Screen
    Aa sheet. Text size, and Light · Sepia · Dark for the Reader.
  6. Screen
    Archive. Same rows. Swipe right → back to Unread. Delete from each row's menu, with undo.
  7. Screen
    Search. On-device, full text, across Unread and Archive, results labelled with which list they're in.

6 · Listen

  1. Action
    ▶ in the Reader.
  2. Screen
    The phone's voice starts at once; words highlight as they're spoken; the mini player docks (play/pause, skip ±15 s, speed). The article joins the Listen tab.
  3. Silent
    Ask the server for the better voice. It's cached per article and used from the next play; it never swaps voices mid-article.
  4. Screen
    Lock screen and car controls. Tap → Reader at the spoken word new.
  5. Screen
    Listen tab: Now playing card, then everything played, most recent first changed. Play all continues down that list; it's the only auto-continue.
  6. Unhappy
    Better voice unavailable for an article → a quiet note; the phone's voice carries on. Offline → downloaded audio plays, everything else uses the phone's voice.

7 · You

  1. Screen
    You. Header: nostr name and picture if signed in with a nostr app, otherwise "47 saves · 12 listened" new. Then: Back up your shelf card (while not done), Recovery code, Add another device, Connected browsers, Voice, Advanced, Delete my data.
  2. Screen
    Recovery code sheet. Twelve numbered words, Copy, one line on when you'd need it. Viewing it clears "Not written down".
  3. Screen
    Add another device. QR plus six-digit code, five minutes. Expired → "Code expired, show a new one".
  4. Screen
    Connected browsers. List, Connect a browser, Disconnect with its dialog: "Pages saved from that browser will be ignored. Uninstall the extension there or connect it again."
  5. Screen
    Voice. Which better voice to use; the phone's voice as the fallback.
  6. Screen
    Advanced. Relays (the one place the word appears), Export, Use my nostr app instead new, which moves every save across, with the same Keep backup copies switch (decision 76).
  7. Screen
    Delete my data. What goes, and what can only be asked of independent relays. Type DELETE to confirm new. Done → Welcome.

Screen inventory for the mockups

Built locally as HTML prototypes, phone-sized (360 × 800, checked at 412 × 915), light and dark, each state from the matrix as its own frame. Batches, in order:

  1. Core loop: Saves (all states), Saved sheet, Reader (all states), Aa sheet, end card.
  2. Listen: mini player, Reader playing with highlight, Listen tab, lock screen reference.
  3. First launch and return: Welcome, Bring back your shelf, scan, recovery code, nostr sign-in, Restoring.
  4. You: You, recovery code sheet, Add another device, Connected browsers and Connect this browser?, Voice, Advanced, Delete my data.
  5. Extension: toast states, options page states.
